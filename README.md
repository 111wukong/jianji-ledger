# 简记 · 不可篡改账本

一个「记下就改不了」的记账工具。所有记录只追加、不可修改、不可删除；任何改动都会破坏哈希链并被校验发现。

提供两个形态，共用同一套设计：

| | 本地版 `local/` | 联网版 `web/` |
|---|---|---|
| 形态 | 单文件 HTML，双击即用 | 零依赖 Node.js HTTP 服务 |
| 依赖 | 无（无 CDN、无 npm、可离线） | 仅 Node.js 内置模块 |
| 身份 | 无 | 助记词即身份，私钥签名挑战登录 |
| 账本 | 双账本（个人账 / 公司账），数据隔离 | 多账本（按账本派生密钥与标签） |
| 公开性 | 完全本地 | 公开只放哈希承诺与 Merkle 根，密文永不公开 |
| 他人可见 | 导出的 Excel / PDF 报表 | 公开验证页 + 按账本选择性披露 |

## 设计原则

- **只追加（append-only）**：记录一经写入就没有修改或删除路径。本地版用 SHA-256 哈希链 + 红字冲销；联网版在服务端根本没有 `UPDATE` / `DELETE` 路由，写入前还会校验序号、前序哈希、记录哈希与 ECDSA 签名。
- **记错用红字冲销**：不回写原记录，而是追加一笔等额反向分录。两笔都永久留痕，净额与余额自动抵消。
- **客户端加密**：明文在浏览器里用助记词派生的密钥加密后才上传。服务端只见密文、不可逆的账本标签、哈希与签名。
- **公开哈希承诺**：对外只公开序号、前序哈希、本条哈希、时间戳、签名与全局 Merkle 根。任何人都能验证「谁在何时记过一笔、之后没被改动」，但看不到记了什么。
- **锚定证明**：每写入一个事件就把当时的 Merkle 根串进第二条只追加的锚链。保存锚点后，可随时做一致性校验，发现服务端整体替换或回滚历史。

## 快速开始

### 本地版

直接用浏览器打开 `local/index.html`。首次打开是示例数据，点顶部横幅的「清空示例数据」即可开始记自己的账。

功能：个人账 / 公司账双账本、资金台账（增加 / 减少 / 逐笔滚动余额）、预算、账户余额、AI 洞察、明细搜索筛选、Excel（6 个工作表）/ PDF / CSV / JSON 导出、独立 `.jsonl` 账本文件（卸载浏览器也不丢）。

`local/` 下另附两份真实导出的 Excel 报表样例，可直接打开查看成品格式。

### 联网版

```bash
cd web
npm start                 # 等价于 node server.mjs
# 默认 http://127.0.0.1:3000
PORT=8080 npm start       # 自定义端口
```

服务监听环境变量 `PORT` 并绑定 `0.0.0.0`，可部署到任意单端口 HTTP 托管环境。数据写在 `web/data/events.jsonl`（只追加事件日志，运行时自动创建）。

打开首页后：

1. 「生成我的专属密钥」→ 抄下 16 个助记词（**唯一恢复方式，丢了没有任何人能找回**）。
2. 记一笔：内容在浏览器加密、签名后上传。
3. 「公开验证」页可独立校验哈希链、验签、锚链一致性并保存/导出锚定证明。
4. 「授权查看」页可把某个账本授权给指定身份指纹看懂，也可撤销。
5. `/verify.html`（或 `/verify.html?fp=<身份指纹>`）是无需登录的公开验证页，可把链接发给任何人。

助记词 + 「身份与备份」里导出的加密账本，可在服务端被彻底清空后完整恢复：重新注册身份并逐条重放原记录，每条仍要通过哈希与签名校验，最终 Merkle 根与丢失前一致。

## 联网版 API

公开（无需登录，永不含密文）：

| 接口 | 说明 |
|---|---|
| `GET /api/health` | 状态、身份数、记录数、Merkle 根、锚链头 |
| `GET /api/anchors` | 全局哈希承诺、各身份链头、近期锚点 |
| `GET /api/anchors/:fp` | 指定身份的纯哈希链（序号 / 前序哈希 / 本条哈希 / 时间戳 / 签名 / 公钥） |
| `GET /api/anchor-proof` | 自包含锚定证明：完整锚链 + 各身份链头 |
| `GET /api/pub/:fp` | 身份公钥（用于授权与验签） |
| `POST /api/verify` | 服务端辅助校验 |
| `POST /api/lookup` | 按助记词校验值找回加密的私钥包 |

会话与写入（需有效签名会话）：

`POST /api/challenge` → `POST /api/session` → `GET /api/me` / `POST /api/entries` / `GET /api/entries` / `POST /api/grants` / `GET /api/grants` / `POST /api/revoke` / `GET /api/shared`。

服务端事件日志只有 `identity` / `entry` / `grant` / `revoke` / `anchor` 五类，没有任何改删事件。

## 安全模型（请认真读）

**能防**：记录被改、被删、被乱序插入；服务端单方面悄悄修改历史（哈希链 + 签名会暴露）；服务端整体替换或回滚存储（锚链一致性校验会暴露）；服务端被拖库导致明文泄露（服务端只有密文）；密文大小泄露摘要长度（已做 512 字节定长填充）。

**不能防**：

- 客户端设备被攻破、助记词被钓鱼或泄露——拿到助记词就等于拿到全部身份与账本。
- 服务端运营方同时替换存储**和**你保存的锚定证明。要做到审计级不可篡改，需要把 Merkle 根锚定到真正外部第三方（公开时间戳服务、多机构交叉签名或公链），本项目尚未实现。
- 元数据泄露：记账时间、笔数、频率、IP、记录大小写仍可被服务端观察。
- 授权撤销只能阻止之后继续读取；对方在授权期间看过或保存的内容，密码学上无法收回。
- 托管环境的文件系统若不持久，`web/data/events.jsonl` 会随环境重建丢失。客户端保留完整账本与导出文件，可重新提交恢复；生产部署应挂载持久卷或改用外部对象存储。

**这不是审计级会计系统**，请勿直接用于法定账簿、税务申报或需要法律效力的合规场景。
