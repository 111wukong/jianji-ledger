# 简记开发指南

## 统一架构边界

主应用是 `web/` 下的离线优先账本，不再拆分“本地版”和“联网版”两条产品流程。

- `web/public/app.js`：身份、加密、界面与同步编排。明文只允许存在于当前页面内存，不得写入 IndexedDB、localStorage、日志或锚点。
- `web/public/offline-store.js`：IndexedDB 持久化。记录对象只含密文、签名、哈希、序号和待同步标志；刷新服务端时不得清空待上传记录。
- `web/public/sync-core.cjs`：纯同步计划，浏览器与 Node.js 共用。负责严格前缀检查、已有记录识别、连续上传后缀和分叉检测，不依赖 DOM 或网络。
- `web/public/sw.js`：缓存应用外壳，不拦截 `/api/`。修改静态资源后应递增缓存版本。
- `web/server.mjs`：零依赖 Node.js 服务，只追加事件，不增加修改或删除路由。启动重放后持久打开日志描述符，写入保持同步顺序。
- `web/public/anchor-core.cjs`：服务端锚链和 GitHub 外部锚点的纯校验逻辑。
- `scripts/publish-anchor.mjs`：读取公开证明、独立重算、生成不含密文的 GitHub 锚点。
- `local/src/ledger-core.cjs` 与 `local/src/index.template.html`：早期单文件工具的兼容源码，不是主应用的新功能入口。

## 同步不变量

1. 每条记录先在本机完成加密、签名、`seq / prevHash / hash` 接续，再进入待同步队列。
2. 上传顺序必须与本地链顺序一致，每批 1–50 条。
3. 同一 `hash` 已存在时只做幂等确认，不重复追加。
4. 批量接口中途失败时，客户端先保存已返回的 `accepted / existing` 结果，再暂停后续队列。
5. 本机已同步记录必须是服务端响应的严格前缀；服务端缩短或替换前缀时停止同步。
6. 多设备同序号不同哈希属于分叉。不得通过改序号、重签或覆盖写悄悄“修复”。
7. 网络失败与业务分叉必须显示不同状态；不得把分叉显示成普通离线。
8. 公开锚点只含哈希承诺，不得包含密文、助记词、密钥包或账目明文。

## 常用命令

```bash
npm run build       # 从模板重新生成兼容旧版 local/index.html
npm test            # Node.js 内置核心测试，无第三方依赖
npm start           # 启动统一应用，默认 3000 端口
npm run test:browser # 可选：真实 Chromium 离线同步回归
```

浏览器回归可用环境变量指定现有安装：

```bash
PLAYWRIGHT_PATH=/path/to/playwright \
CHROMIUM_PATH=/usr/bin/chromium \
BASE_URL=http://127.0.0.1:3000 \
node tests/browser-offline.mjs
```

浏览器测试会创建测试身份和记录，只能对空白测试服务运行。提交前至少执行：

```bash
npm run build
npm test
```

并把重新生成的 `local/index.html` 一起提交。CI 会再次构建并检查生成文件同步。

## 测试约定

核心测试至少覆盖：

1. SHA-256 与平台标准实现一致，包含空串、中文与长文本。
2. 金额、备注、序号、链头变化以及删史都会导致校验失败。
3. 红字冲销不改原记录，同一原记录不能重复冲销。
4. 恢复只能向前，较短备份或不同前缀必须被拒绝。
5. 外部锚点必须能在当前锚链中找到完全相同的一条；快照滞后与历史回滚显示不同结论。
6. 响应丢失后的重试被识别为 `existing`，不会重复上传。
7. 同序号不同哈希、非连续离线队列、服务端缩短与前缀替换都必须停止同步。
8. 上传批次最多 50 条且保持原顺序。

真实浏览器回归至少覆盖：离线记账、断网刷新后恢复、联网自动上传、重复同步去重、红字冲销、375px 无横向溢出、无控制台错误。不能只以“页面能打开”作为完成标准。

## 外部锚定发布约束

- 发布脚本只读取 `/api/anchor-proof`，不得读取 `/api/entries`、密钥包或助记词。
- `anchoring/latest.json` 只包含公开哈希、序号、时间戳和账本公开地址。
- 同一个 `anchor.hash` 不重复提交。
- 服务端证明自身校验失败时，发布脚本必须退出失败。
- 锚定 GitHub 仓库与账号应尽量由独立于账本运营方的人员控制。

## 下一轮建议

优先级从高到低：服务端存储层抽象与持久化备份、多设备分叉的人工核对与显式重建工具、共享账本多人操作流程、按月选择性披露。自动冲突合并与只追加模型存在天然张力，不应为了同步体验引入覆盖写。
