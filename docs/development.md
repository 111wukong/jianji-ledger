# 简记开发指南

## 统一架构边界

主应用是 `web/` 下的离线优先账本，不再拆分“本地版”和“联网版”两条产品流程。

- `web/public/app.js`：身份、加密、界面与同步编排。明文只允许存在于当前页面内存，不得写入 IndexedDB、localStorage、日志或锚点。
- `web/public/offline-store.js`：IndexedDB 持久化（`entries` / `archive` / `meta` 三个 store）。`entries` 只含密文、签名、哈希、序号和待同步标志，刷新服务端时不得清空待上传记录；`archive` 是后台静默维护的全量双层加密归档。`DB_VERSION` 变更时必须只增 store、不破坏旧数据。
- `web/public/archive-core.cjs`：归档密码学（PBKDF2 60 万次分域派生、AES-256-GCM + AAD 绑定、版本 MAC 防降级、512B 填充），浏览器与 Node 共用同一份实现。任何改动都要同步更新 `tests/archive-core.test.mjs`，并确认旧归档仍可解开。
- `web/public/sync-core.cjs`：纯同步计划，浏览器与 Node.js 共用。负责严格前缀检查、已有记录识别、连续上传后缀和分叉检测，不依赖 DOM 或网络。
- `web/public/sw.js`：缓存应用外壳，不拦截 `/api/`。修改静态资源后应递增缓存版本。
- `web/server.mjs`：零依赖 Node.js 服务，只追加事件，不增加修改或删除路由。启动重放时校验 JSON 完整性与锚链连续性，任何损坏都拒绝启动；重放后持久打开日志描述符，写入保持同步顺序。数据目录可用 `LEDGER_DATA_DIR` 覆盖。
- `profile` 事件：用主密钥加密的账本目录，只追加、取最新值。账本名参与派生 `bookKey` / `bookTag`，必须与身份一起可恢复。
- `web/public/anchor-core.cjs`：服务端锚链和 GitHub 外部锚点的纯校验逻辑。
- `scripts/publish-anchor.mjs`：读取公开证明、独立重算、生成不含密文的 GitHub 锚点。
- `local/src/ledger-core.cjs` 与 `local/src/index.template.html`：早期单文件工具的兼容源码，不是主应用的新功能入口。

## 同步不变量

1. 每条记录先在本机完成加密、签名、`seq / prevHash / hash` 接续，再进入待同步队列。
2. 上传顺序必须与本地链顺序一致，每批 1–50 条。
3. 同一 `hash` 已存在时只做幂等确认，不重复追加。
4. 批量接口中途失败时，客户端先保存已返回的 `accepted / existing` 结果，再暂停后续队列。
5. 本机已同步记录必须是服务端响应的严格前缀；服务端缩短或替换前缀时停止同步。
6. 多设备同序号不同哈希属于分叉。不得通过改序号、重签或覆盖写悄悄“修复”。
7. 网络失败与业务分叉必须显示不同状态；不得把分叉显示成普通离线。
8. 公开锚点只含哈希承诺，不得包含密文、助记词、密钥包或账目明文。
9. 每轮同步先用 `/api/status` 轻量探测。链高、链头、锚链头与授权版本都没变化时，不得拉取全量密文或全量锚定证明，也不得重写本机数据库。
10. `?since=` 只是传输优化：必须把「本机已同步前缀 + 增量后缀」拼成完整链，再执行第 5、6、7 条检查；不得直接信任增量片段。
11. 账本目录必须随身份可恢复，且新增账本后要追加 `profile` 事件。任何无法解密的密文都必须显式计数并提示，不得静默从合计中消失。
12. 事件日志出现损坏行、缺失中间行或锚链断裂时，服务端必须拒绝启动；静默跳过等于放弃不可篡改保证。
13. 本机归档只保存当前身份有权看到的内容（自己的 + 被授权共享的），不得把其他身份的密文铺到每台设备；归档密钥必须独立于身份/账本密钥分域派生。
14. 归档必须「静默但不隐瞒」：不弹窗、不阻塞同步、无加载态，同时欢迎页有告知、身份备份页有状态与清除/恢复入口。
15. 分叉重建必须先强制下载本机完整备份、二次确认，且不得删除加密归档；不得静默合并或改写已签名记录。
16. 归档行必须自包含非秘密的密钥参数（salt / 迭代次数 / 版本 MAC），保证「归档文件 + 助记词」可脱离原设备独立恢复；导入归档必须逐条解密校验后才写入。
17. 每次发布前用 `npm run drill:restore` 验证「服务关闭 + 数据目录全删 → 仅凭加密备份还原」路径仍然成立；CI 已包含该步骤。
18. 快捷解锁只能用「信封加密」：随机 salt + PBKDF2 60 万次派生 KEK，包住助记词与私钥，凭据只存本机、绝不上传；必须校验版本/迭代次数防降级、限制尝试次数、可随时关闭，并在界面写清「PIN 只是本机便利，助记词才是跨设备恢复凭据」。
19. 身份凭据文件是明文最高敏感材料，导出前必须二次确认并提示离线保管；导入校验必须同时要求 16 词助记词与两把私钥，且不得依赖服务端。
20. 「记下」的操作路径要尽可能短：首页随手记默认今天与当前账本，提交后保持金额输入框焦点以便连续记账；完整字段表单仍保留在「记一笔」页。
21. 不要引入 CRDT 自动合并。账本的正确去中心化形态是「多副本 + gossip + 分叉显式保留」；合并已签名记录等于篡改。
22. 加密备份必须支持多目标且落在不同物理位置；守护进程用固定心跳 + 时间戳判断，**30 天这类长周期毫秒数不得直接传给 `setInterval`**（超过 2^31-1 会被截断成 1ms 疯狂重复）。自动生成之外还必须自动校验最新备份。
23. `/api/replicas` 只暴露副本份数、目标数、时间与体积，不得返回路径或账目内容；客户端必须对待同步记录明确标注「仅本机一份」。

## 常用命令

```bash
npm run build       # 从模板重新生成兼容旧版 local/index.html
npm test            # 32 项测试：纯函数核心 + 真实进程 HTTP 集成，无第三方依赖
npm start           # 启动统一应用，默认 3000 端口
npm run test:browser     # 可选：Playwright 真实浏览器回归
npm run test:browser:cdp # 可选：零依赖 CDP 回归（系统 Chrome/Chromium 即可）
LEDGER_BACKUP_PASSPHRASE='...' npm run backup          # 加密异地备份
LEDGER_BACKUP_PASSPHRASE='...' npm run backup:verify -- <file> --out <path>  # 校验/还原
```

浏览器回归可用环境变量指定现有安装：

```bash
PLAYWRIGHT_PATH=/path/to/playwright \
CHROMIUM_PATH=/usr/bin/chromium \
BASE_URL=http://127.0.0.1:3000 \
node tests/browser-offline.mjs
```

浏览器测试会创建测试身份和记录，只能对空白测试服务运行。提交前至少执行：

```bash
npm run build
npm test
```

并把重新生成的 `local/index.html` 一起提交。CI 会再次构建并检查生成文件同步。

## 测试约定

核心测试至少覆盖：

1. SHA-256 与平台标准实现一致，包含空串、中文与长文本。
2. 金额、备注、序号、链头变化以及删史都会导致校验失败。
3. 红字冲销不改原记录，同一原记录不能重复冲销。
4. 恢复只能向前，较短备份或不同前缀必须被拒绝。
5. 外部锚点必须能在当前锚链中找到完全相同的一条；快照滞后与历史回滚显示不同结论。
6. 响应丢失后的重试被识别为 `existing`，不会重复上传。
7. 同序号不同哈希、非连续离线队列、服务端缩短与前缀替换都必须停止同步。
8. 上传批次最多 50 条且保持原顺序。
9. 服务端集成测试必须覆盖：挑战绑定身份、顺序写入、幂等重试、分叉拒绝、`since` 增量后缀、`/api/verify` 拒绝伪造链、加密账本目录随身份恢复、重启重放、损坏日志拒绝启动、邀请码闸门、严格 CSP、加密备份的篡改检测。
10. 归档测试必须覆盖：KDF 参数（60 万次、随机 salt）、错误助记词、版本/迭代次数/MAC 防降级、AAD 防搬移、512B 填充、密文中不出现原始 cipher；浏览器回归还要验证后台归档生成、防篡改与从归档恢复。

真实浏览器回归至少覆盖：离线记账、断网刷新后恢复、联网自动上传、重复同步去重、红字冲销、375px 无横向溢出、无控制台错误。不能只以“页面能打开”作为完成标准。
`tests/browser-cdp.mjs` 不依赖 Playwright，额外覆盖新增账本写入服务端加密目录、换设备恢复后全部密文可解密，以及两轮空闲同步必须零全量请求；可用 `CHROME_PATH` 指定浏览器。两个浏览器脚本都只对临时服务与临时配置运行。

## 外部锚定发布约束

- 发布脚本只读取 `/api/anchor-proof`，不得读取 `/api/entries`、密钥包或助记词。
- `anchoring/latest.json` 只包含公开哈希、序号、时间戳和账本公开地址。
- 同一个 `anchor.hash` 不重复提交。
- 服务端证明自身校验失败时，发布脚本必须退出失败。
- 锚定 GitHub 仓库与账号应尽量由独立于账本运营方的人员控制。

## 下一轮建议

优先级从高到低：标准 BIP39 助记词（含校验和）与带拉伸的 KDF（**需旧身份迁移方案，会影响 verifier 派生，不能静默升级**）、多设备分叉的人工核对与显式重建工具、服务端自动异地备份、共享账本多人操作流程、按月选择性披露。自动冲突合并与只追加模型存在天然张力，不应为了同步体验引入覆盖写。

已完成：账本目录随身份恢复、无法解密记录显式提示、`/api/verify` 绑定已登记身份、轻量探测与增量同步、日志损坏 fail-fast、服务端 HTTP 集成测试、容器 `HOST` 与持久卷；本机加密归档、分叉证据导出与显式重建、邀请码闸门、严格 CSP 与安全头、加密异地备份与校验、健康降级标志。

调研借鉴（Evolu / Anytype / Cryptomator / local-first 实践）：随机主密钥 + 分域派生、口令只做 KEK、AEAD 的 AAD 绑定、格式版本 MAC 防降级、长度填充防流量分析、全库加密落盘、同步状态「安静可见」而非隐瞒。当前身份体系仍用 16 词自定义词表（非 BIP39、无校验和、HKDF 无拉伸），归档层已按 OWASP 量级做 PBKDF2 补偿；身份级升级需迁移方案。
