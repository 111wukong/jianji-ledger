# 两人合伙对账：当前版本使用方案

这是一个基于现有功能的手动流程，不代表系统已经提供自动对账或双人共同签名。

## 适用场景

两人共同经营小生意、工作室或项目，希望做到：支出记录不能悄悄改删；一方可以把某本账授权给另一方查看；月底可以核对链头、公开哈希和资金报表。

## 首次准备

1. 双方各自生成助记词并离线抄写。助记词不能通过微信聊天或群文件发送。
2. 双方在「身份与备份」中复制自己的身份指纹，再当面或通过已确认的联系方式交换指纹。
3. 记账方新建一本独立账本，例如「工作室经营账」，不要与个人账混用。
4. 在「授权查看」中按对方身份指纹授权这本账。授权目前是整本账本粒度，不能按月份裁剪。

## 日常记账

- 每笔支出写清日期、金额、往来对象、凭证号和摘要；原始票据仍按双方现有方式保存。
- 记错时不要另写说明要求对方“忽略原记录”，应追加等额反向冲销记录，让原记录与冲销记录同时保留。
- 另一方定期在「授权查看」中核对流水。对某笔有异议时，线下确认后由记账方追加新的更正分录，不覆盖旧账。

## 月底对账

1. 双方分别打开公开验证页，确认服务端锚链完整。
2. 打开「GitHub 外部锚定」，点击「一键核验 GitHub 锚点」，或导入同一个锚点 JSON 文件。
3. 记录月末的账本头、Merkle 根、外部锚点序号与 GitHub 提交链接。
4. 若显示「旧锚点有效；之后还有事件等待锚定」，先等待下一次自动任务或手动运行工作流，再把最新锚点纳入月末归档。
5. 若显示「锚点不在当前锚链中」或「历史回滚」，停止对账并保留双方证据，不要继续以该服务端状态为准。

## 当前边界

- 公共验证只能证明哈希承诺，不能证明某笔支出在现实中真实发生；票据和业务真实性仍需双方审核。
- 授权撤销只能阻止之后的读取，不能收回对方已经看到或保存的内容。
- 当前没有双人共同签名、自动票据匹配、按月授权和自动差异报告；这些应作为后续独立功能开发，不能用文档流程冒充。
